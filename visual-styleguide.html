Supersedes logo.html, field-guide.html, colors.css, typography.css

How the system speaks, and every component it speaks with.

Ghostmaxxing is a public research lab for testing, explaining and questioning facial recognition through browser-based AR camouflage, adversarial-makeup experiments and a curated references archive. This document carries the identity that work is delivered in: voice, colour, type, the mark, and the camera-lens motif. Each component appears here as the live thing rather than a picture of it.

01

The system

Four layers, each allowed to know about the ones above it and nothing below. The rule that keeps this honest: a component never positions itself on a page. cameras.css draws a camera and sets the state of its lens; where that camera goes is genealogy.css's business.

One stylesheet link per page. styles.css is the root import list and the import order is the architecture.

LayerFileHolds
tokenstokens/colors.css
tokens/typography.css		Colour and type. Nothing but :root. Icons are assets, not tokens — they do not go here.
basebase.cssThe reset. Knows about no page and no component.
componentscomponents/logo.css
components/cameras.css		Used by more than one page. Draw and state, never placement.
pagespages/genealogy.css
pages/homepage.css		One per page. Layout only.

A design token is a named design decision — the smallest indivisible unit of the system: a colour, a size, a typeface. The term is standard; it originates at Salesforce and is now a W3C draft. It is worth being strict about, because the moment a component rule lands in a token file, that file stops being a source of truth and becomes another place to look.

02

Voice

Activist first, culturally staged second, editorial third. Not an academic paper, not a cybersecurity product, not a policy campaign. It should sound like people who understand code, research, public space and political risk — in that combination, which is rarer than any one of them.

No emoji. Direct and precise, never sloganistic.

Four principles

01Test, do not trust. A face match is a system output, not a truth. Never "this defeats surveillance."
02No false safety. Always name the conditions: model, camera, light, pose, distance. Never "protect yourself" or "become invisible."
03The archive is evidence, not an appendix. Every reference names what is testable and what is limited.
04Every claim is graded before it ships. See the ladder below.

The claims ladder

Safe
A face match is a system output, not a truth.

True independent of conditions. Ships as written.

Conditional
In our tests, this pattern lowered detection confidence on one open model at close range under even light.

True under stated conditions, and the conditions are stated. Names the model, the distance, the light. Never generalises past what was measured.

Research
Whether this transfers to deployed systems is untested.

An open question, published as an open question. This grade is a feature — it is what makes the other two credible.

Unsafe
Ghostmaxxing protects you from facial recognition.

Does not ship. Not softened, not hedged, not moved below the fold — cut.

Vocabulary

Use

  • face recognition
  • face detection
  • biometric surveillance
  • adversarial makeup
  • Ghostyle
  • reference archive
  • testability
  • reporting node
  • local experiment

Avoid, or qualify heavily

  • invisibility
  • anonymity guarantee
  • protection
  • foolproof

  • untrackable
  • undetectable

One tension worth naming: the genealogy page is built on the word defeated — "defeated in 2016", the spent lens state. That word is on the avoid list. It survives there because it describes a historical, documented, past-tense event about a specific model, not a promise to the reader about their own face. If it ever slips into the present tense or the second person, it has become an unsafe claim.

03

Colour

One palette, one file. styles/tokens.css is the only place a --gm-* value may be defined. It absorbed colors.css and typography.css, and a third copy that was hiding in a :root block in pages.css — which is why about.html and report.html used to render a different orange from the homepage. The swatches below are read live from the stylesheet, so if one is wrong the token is wrong.

One accepted anomaly. The smoke and pyre motifs bake four greens as literal hex across roughly 2,000 <circle> elements, and they are the old greens: #0a4d3a, #063f32, #04302a, #031f19. They are painted files behind background-image, so they cannot follow a token. Re-exporting them to shift four dark greens by a few percent was judged not worth the risk to a keeper page. They are declared as --gm-smoke-1…4 so the values are centralized and greppable. Do not use them for anything else. If the motifs are ever re-exported, re-export to the --gm-green-* ramp and delete those four tokens.

One background: surveillance orange. A poster-wall colour — a public notice pasted in the street — not neon, not cyberpunk. Everything else is seated on it.

Every swatch below is read from the stylesheet at runtime, so this page cannot drift from the token file the way a hardcoded chart does. A swatch outlined in red means that token is not defined.

The greens are ordered, and the order is the contract

Light to dark: --gm-green-soft reads as a surface, --gm-green draws the lines on it, --gm-green-deep is the barrel of every camera lens, --gm-green-night is the ground. Nothing should pick a green by eye.

The pink rule

--gm-pink · seating

on cream — correct
on soil — correct
bare on orange — never

Pink against the page orange sits near 1.15:1. That is not low contrast, it is no contrast — the shape simply stops existing. It always needs cream, soil or dark green seated underneath.

UseThe cut / defeated state — the residue ring of a spent lens.
UseThe ring of the logo mark, and the one short line through the cut lens.
UsePage accents: tags, rules, link underlines — on a seated surface.
NeverBare on --gm-bg with nothing between.
NeverAs body text.

This supersedes the older reservation of pink to lenses only. It is now a page accent — but the seating requirement is not a preference, it is the reason the earlier rule was written that strictly.

04

Type

Three families, each with exactly one job. The discipline is the point: as soon as the mono is allowed into a paragraph or the serif into a button, the hierarchy stops carrying meaning and becomes decoration.

Disrupt the read.

--serif · Newsreader · poster headlines only — h1, h2, h3, wordmark, pull-quotes

Ghostmaxxing tests face-recognition camouflage through browser-based overlays and local experiments.

--sans · Atkinson Hyperlegible · every reading and UI surface. Weights 400 and 700, nothing between

2019 · Directly testable · 04

--mono · JetBrains Mono · metadata only — years, tags, testability badges, section numbers. Never body text

The scale, rendered live

Only the four display steps are fluid, and all of them interpolate across the same 400px → 1440px range — which is why they scale in step instead of crossing over at some awkward width. Reading sizes are fixed on purpose: body text that grows with the window gets harder to read, not easier.

Atkinson ships two weights. Asking for 500, 600 or 650 makes the browser synthesise one, and the result is visibly uneven against the real 400 beside it.

Shape & surface

The look is poster and archive, not SaaS dashboard. That is a shape decision before it is a colour one, and it is the fastest thing to lose.

Correct

2016 · Conditional

CNN face embeddings

Square corners, 2px solid ink border, flat fill.

Wrong

2016 · Conditional

CNN face embeddings

Rounded corner, coloured left border, drop shadow. The default card of every dashboard on the internet, and it makes an evidence archive look like a product tour.

DoSolid 2px ink borders as the primary separator.
DoFlat colour fields: orange, soil, cream.
NeverDrop shadows. There are none in the system.
NeverBorder radius on cards and panels.
NeverGradients — with one exception: the optional very-low-opacity pink/soil pinwheel gutter pattern, desktop ≥1440px only, and never pink alone on orange.

Note a live contradiction. base.css currently paints body with a radial gradient plus a linear gradient down to --gm-bg-deep. That is two gradients on the flattest surface in the system. Either the rule loses its "flat fields" wording or the reset loses its gradients — they cannot both be right.

The mark

A rail across the top with two stems. Two lenses hang from it — green-soft body, green-deep ring, live yellow iris, no cut. Beneath them a gust of pink wind. Beneath that a single spent lens, pink ring and dark iris, with a small green flame over it.

That is the argument in one mark. The two at the top are the undefeated present — the pair at the canopy of the genealogy. The gust is an intervention that was demonstrated and worked. The spent lens is the era it put out, and the flame is that era still burning as fuel for the next one.

DoPick the cut by surface: -ondark on soil and green, -onlight or mark-color on cream and orange, -mono-ink / -mono-cream for one colour.
DoUse a -small cut below about 28px. It drops the spent lens and the flame, which turn to mush at that size, and enlarges the rail and the two lenses.
NeverShow the two top lenses cut, ringed pink, or dark-irised. They are undefeated by definition. If that ever changes it is a research finding and a content change, not a styling one.
NeverAnimate the lenses. Only the gust moves.

Superseded, so you do not go looking for it. The mark was previously a single disc with four pink shards radiating from the centre, and before that this section described a column of four lenses with the top one cut. Both are gone. There is no .gm-logo-shard, no gm-logo-stutter, and no rotation anywhere in logo.css — the only animation is a dash sweeping along the gust.

Motion

.gm-logo--animated .gm-logo-shard {
  animation: gm-logo-stutter
    var(--gm-logo-duration) infinite
    steps(1, end);
}

Five uneven steps: two long holds, a burst, then round. steps(1, end) makes every keyframe a hard cut. The mark must never appear to sweep — sweeping reads as progress, and this is not progress. It is a machine retrying a read and failing.

transform-origin is set in user units (32px 32px), matching the SVG pivot exactly. A percentage would resolve against the element box and drift the moment the viewBox is not square.

Under prefers-reduced-motion the shard stops but stays put. It carries information; resetting its rotation would remove some.

This is the only motion in the system. Everything else, including lens states, is instant.

07

Camera anatomy

One custom fleet, no icon font and no third-party set. Five parts, five classes, always drawn in this order, on a 0 0 100 100 viewBox. Every icon carries no colour of its own — the paint comes from cameras.css, so one rule restyles the whole fleet.

cam-dome · exploded

.cam-mountBracket, pole or arm. Stroke only, never filled, so it can pass behind other things.
.cam-shellThe housing. This is the shape the model is recognised by, so it is the one thing that must never be obscured.
.cam-lensThe dark barrel, always --gm-green-deep. It does not change with state — hardware does not care whether it is working.
.cam-irisThe coloured centre, and the only part with an id.
.cam-glintThe highlight. Decorative: no id, no meaning beyond "this lens is live".

Proportions, not eyeballs

iris  = 0.44 × lens radius
glint = 0.17 × lens radius,
        offset 0.30 × up and left

Written down so the next camera is derived rather than guessed. The old fleet carried these values in two of nine files and drifted everywhere else.

The class contract, now real

Closed. images/icons/cam-*.svg are the class-driven re-export — no presentation attributes, state by attribute — and they are the source of truth for the fleet. The old assets/icons/ copies with baked hex are deleted. What that change exposed is §12: a class-driven file has to be inlined, and every <img> pointing at one was rendering black.

The id convention

<circle class="cam-iris" id="iris-dome"
        cx="50" cy="44" r="6.6"/>

<symbol> plus <use> puts the copy in a shadow tree, so #iris-dome becomes unreachable and duplicate ids collide. Each camera appears once per page — inline the SVG and write the id by hand. If a model ever has to appear twice, clone a <template> in script and prefix the ids, which is what this page does for its own repeated specimens.

Six models, one per era of the genealogy. There are no -alive variant files any more — that was nine files describing six objects. State is an attribute, so one drawing covers every condition.

#iris-street

Street pole

Era of vision, 2021 →. The only model whose mount is longer than its housing: it is street furniture first.

#iris-glasses-l / -r

The exception. Their lens body is already cream, so a filled iris makes welding goggles and eats the figure-of-eight silhouette. They get a glass glare instead, plus two void irises that draw nothing but exist as geometry.

Era of depth, 2017–2020. The dot field is the projector and stays dark in every state — it emits, it does not read.

#iris-dome

#iris-bullet

09

Lens states

Three, and there will not be a fourth. Set data-lens on the <svg> or on any ancestor — on an era row it switches every camera in that row at once.

data-lens="live" — or unset

Live

Yellow iris, glint on. Still reading. Not defeated.

data-lens="reading"

Reading

Pink iris, glint off. Transient — it exists for the length of a transition and is never left on a page at rest.

data-lens="spent"

Spent

Dark iris, thin pink residue ring, no glint. Permanent, and deliberately still.

State changes are instant, not animated. A camera having been defeated is information, and information must survive a screenshot, a print, and prefers-reduced-motion. The ring is the residue of the read that failed.

<svg class="cam" data-lens="spent"> ... </svg>      one camera
<section class="era" data-lens="spent"> ... </section>  a whole row
row.dataset.lens = 'spent';                        from script

The specificity trap

[data-lens="spent"] .cam-iris scores 0,2,0 and outranks .cam-iris--void at 0,1,0 — which handed the glasses two pink rings, exactly the welding-goggles look the void iris exists to prevent. The guard is [data-lens] .cam-iris--void, matching specificity and placed after. Do not reorder cameras.css casually.

Stamps

One class, .gm-stamp, for every camera caption. There is no second kind of label. The curve is a property of a stamp, not a separate species — below 700px the same element renders flat, because curved text under a small icon is decoration pretending to be a label.

Every knob is a custom property. Set them on the .gm-stamp, never from script.

Using the SVGs

  

  

    
This section replaces field-guide.html. It answers one question — do I write <img> or do I paste the SVG into the page? — and getting it wrong is the single most common bug in this repo. It is what made every camera on the homepage render as a black blob.

    
The rule, in one sentence. An <img src="x.svg"> is an isolated document. External CSS never reaches inside it, and neither does currentColor from the host page.

  


  
The decision table

  

    
The file is…Through <img> or background-imageInlined in the page

    

      painted — hex baked into fill/stroke attributes
motifs, logo marks, report figures		
      correct
      works, but ignores tokens — it will not follow a palette change
    

    

      class-driven — no presentation attributes at all
every images/icons/cam-*.svg		
      renders black
      correct
    

    

      currentColor
      renders black
      correct
    

  


  
It is worse than uniformly black. .cam-mount is fill: none; stroke: …. Without CSS, a <path> with no fill attribute defaults to filled black — so mounts and brackets come out as solid lumps rather than lines, and the silhouette is unreadable rather than merely dark.


  

    
DoInline anything that needs state, tokens, ids or hover — and make sure the page links styles.css.

    
DoUse <img> or background-image for anything static and decorative, from a painted export.

    
DoClone from a <template> when the same icon is needed many times at runtime. A clone is an ordinary node and gets styled normally.

    
NeverLoad a class-driven or currentColor file through <img>.

    
NeverFix a black icon by baking hex back into images/icons/. That kills the lens states and reintroduces the second palette.

  


  
The currentColor trap

  
mark-mono.svg used to paint entirely with currentColor, and both readme.md and an earlier version of this page said to set CSS color on it. That advice was wrong. Inside an <img>, currentColor resolves against that document's root, which is black — it is not inherited from the host page.

  
<!-- always black, whatever the style attribute says -->
<img src="mark-mono.svg" style="color: var(--gm-cream)">

  
The file is gone. It is now two painted files, mark-mono-ink.svg and mark-mono-cream.svg, and you pick by the surface you are on. Same for mark-small-* and mark-animated-*. If one file really must follow the page colour, inline it or use it as a mask-image with a background-color.

Decision log

  

  

    
What changed, and why — so a future pass does not helpfully restore something that was removed on purpose.

  


  

    
DecisionWhy

    
colors.css is canonicalTwo token files defined different values for the same names. The v2.0 palette in tokens/colors.css wins; the old tokens.css is superseded and should be deleted rather than left to be found.

    
styles.css now existsThe readme described it as the one file to link, but it had never been written. It is the import list, and the order is the layer architecture.

    
Every camera has an irisThe old set encoded "defeated" as the absence of a bright lens. Absence is a poor representation of anything — the dazzled cameras read as holes. State is now carried by colour.

    
The glasses have no irisTheir lens body is already cream, so a filled iris makes welding goggles and eats the silhouette. Glare bars instead, plus void irises for geometry.
