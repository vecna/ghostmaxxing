Field guide: how to read a camera.

Every camera on this site is the same object drawn seven ways, and every one of them can be switched off. This page is the parts list, the state vocabulary, and a working example of each interaction — so that nothing has to be reverse-engineered out of a page that is busy doing something else.

01

Anatomy of a camera

Five parts, five classes, always drawn in this order. Every icon is authored in a 0 0 100 100 viewBox with no colour of its own — the paint comes from cameras.css, so one rule restyles the whole fleet.

The one part that carries an id is the iris. That is the hook everything else hangs off: the state vocabulary in section 03 and the ghostutter targeting in section 04 both address it by name.

cam-dome.svg · exploded

.cam-mountThe bracket, pole or arm. Stroke only, never filled. Not part of the housing, so it can pass behind other things.
.cam-shellThe housing. Cream fill, green outline. This is the shape you recognise the model by, so it is the one thing that must never be obscured.
.cam-lensThe dark barrel. Always --gm-green-deep. It does not change with state — the barrel is hardware, and hardware does not care whether it is working.
.cam-irisThe coloured centre, and the only part with an id. Radius is 0.44 × the lens radius, everywhere, no exceptions.
.cam-glintThe highlight. Radius 0.17 × the lens, offset 0.30 × up and to the left. Decorative: it carries no id and no meaning beyond "this lens is live".

The id convention

<!-- one iris, one id, one camera per page -->
<circle class="cam-iris" id="iris-dome" cx="50" cy="44" r="6.6"/>

iris-{model}   the target. Ghostutter aims here.
lens-{model}   optional, for a mark the size of the whole barrel.

One caveat worth knowing before you build: <symbol> plus <use> puts the copy in a shadow tree, so #iris-dome is not reachable from the page and duplicate ids collide. On genealogy each camera appears exactly once, so inline each SVG and the problem never arises. If a model ever has to appear twice, clone the template in script and prefix the ids — which is what this page does for its own demos below.

02

The catalogue

Seven models, one per era, drawn to the same grammar. Hover any plate to strike that camera: it reads, fails, and stays out. Nothing resets on scroll — press Reset all when you want them back.

#iris-street · images/icons/cam-street.svg

Street pole

Era of vision, 2021 →. The pole is the only model whose mount is longer than its housing: it is street furniture first.

#iris-glasses-l / -r · cam-glasses.svg

Wearable glasses

The exception. A filled iris turns the figure-of-eight into welding goggles, so the glasses get a glass glare instead — and two void irises, which draw nothing but still have a bounding box for the mark to land on.

#iris-cube · cam-cube.svg

Edge AI cube

Era of learning, 2014–2016. The status dot is a .cam-dot, not an iris: it never takes a mark.

#iris-pill · cam-pill.svg

Depth sensor array

Era of depth, 2017–2020. The dot field is the projector, and it stays dark in every state — it emits, it does not read.

#iris-dome · cam-dome.svg

Ceiling dome

Era of measurement, 2010–2013. The dome is the model whose whole point is that you cannot tell which way it is looking — which is why giving it an iris at all is a small editorial decision.

#iris-bullet · cam-bullet.svg

Bullet CCTV

Era of contrast, 2001–2009. The oldest housing still in the tree, and the one most people can name on sight.

03

Lens states

Three states, and there will not be a fourth. Set data-lens on the <svg> or on any ancestor of it — putting it on an era row switches every camera in that row at once.

The important one is spent. It is a still image: dark iris, thin pink residue ring, no glint. That matters because a camera being defeated is information, and information should survive a screenshot, a print, and prefers-reduced-motion. Motion is how the state arrives, never what the state is.

data-lens="live"  (or unset)

Live

Yellow iris, glint on. Still reading. Not defeated.

data-lens="reading"

Reading

Pink iris, glint off. Transient only — this state exists for the ~1.2s a strike lasts and is never left on a page at rest.

data-lens="spent"

Spent

Dark iris, pink ring, no glint. Permanent. The ring is the residue of the read that failed — the only place pink is allowed, per tokens.css.

Setting it

<!-- one camera -->
<svg class="cam" data-lens="spent"> ... </svg>

<!-- a whole era row, cameras and all -->
<div class="era" data-lens="spent"> ... </div>

// or from script
row.dataset.lens = 'spent';

04

Ghostutter

The mark is a six-wedge shard that rotates in hard steps and never settles on its own centre, so it reads as a machine retrying a read rather than as a loading spinner. Four ways to run it, in rough order of how often you will want them.

A · By id, from script — the one you asked for

Ghostutter.cover('#iris-dome')

Cover one target

No pixel coordinate is written anywhere. cover() reads the target's own getBBox() and inserts the mark as its sibling — same local user space, so the camera's matrix, the tree's scale and the viewBox all apply to both equally, at any size, for free.

// aim at any element with an id
Ghostutter.cover('#iris-dome');
Ghostutter.cover('#iris-dome', { run: true });
Ghostutter.cover('#iris-dome', { scale: 1.9 });
Ghostutter.clear('#iris-dome');

// it returns the mark, so modifiers still work
var m = Ghostutter.cover('#iris-cube');
m.classList.add('ghostutter--panic');

Inside an SVG the mark must be <g class="ghostutter"> with real paths — never <use>. ghostutter.css exempts img, svg and g from the CSS mask but not use, so a <use> gets masked twice and disappears. cover() builds the right thing for you.

B · The strike — read, fail, go out

Ghostutter.strike('#iris-cube')

One-shot

This is what genealogy uses. Rather than a field of permanent spinners, each camera goes out once as it scrolls into view — staggered, so it reads as a sequence rather than a carousel.

Ghostutter.strike('#iris-cube');
Ghostutter.strike('#iris-cube', { hold: 1600 });

// declarative: fires once, on scroll into view
<a class="era"
   data-strike="#iris-cube"
   data-strike-delay="180">

// arm() runs on DOMContentLoaded already;
// call it again after injecting markup
Ghostutter.arm(container);

Under prefers-reduced-motion the lens goes straight to spent and no mark is ever created. The information lands; the movement does not.

C · From CSS alone, no script at all

data-ghostutter="hover" on an ancestor

Hover / focus

Put the attribute on the row, card or link — the whole band becomes the hit area, not the 27px mark. Keyboard focus counts, which is why the ancestor needs tabindex="0" if it is not already focusable.

.ghostutter--always

Always

Runs unconditionally. Use sparingly: one is a signal, six at once is wallpaper. Reserved for a single hero camera or the loader.

.ghostutter--still

Still

The escape hatch. Forces one mark to hold position inside an ancestor that is otherwise hovering. Hover this plate: nothing moves.

D · Profiles and speeds

Combine freely — .ghostutter.ghostutter--smooth.ghostutter--slow is valid. All four below are running so you can compare them side by side; on a real page you would pick one.

(default) — stutter

Stutter

Two long holds and a burst. A machine retrying. The default, and the right one at 40px and up.

.ghostutter--panic

Panic

Evenly spaced steps, no dwell. For marks under ~24px, where the long holds just read as broken rendering.

.ghostutter--smooth.ghostutter--slow

Smooth, slow

Continuous rotation. Reads as machinery working, not failing — the opposite meaning. Correct for the footer band, wrong for a defeated lens.

05

Stamps

One class, .gm-stamp, for every camera caption. There is no second kind of label: the curve is a property of the stamp, not a separate species. Below 700px the same element renders flat, because curved text under a small icon is decoration pretending to be a label.

Every knob is a CSS custom property — set them on the .gm-stamp, never in script. Drag the sliders and watch the declaration underneath update.

PropertyWhat it does
--arc-modearc or flat. Flat skips the layout pass entirely and leaves ordinary centred text.
--arc-radiusCircle centre to the middle of each letter, in px. auto = half the icon height + 16.
--arc-centre-yCircle centre relative to the <p>'s own top edge. Negative moves it up inside the icon.
--arc-spreadLetter spacing along the arc. 1 is the font's natural advance — glyphs are never distorted, only repositioned.
--arc-flip0 = readable along the bottom of the circle. 1 = letter tops point outward.

Two passes, and the second is the reason this looks right: glyphs are laid out flat first to measure their real advance widths, then placed along the arc by arc length. Spacing an even angle per character instead is what makes most curved-text implementations look like a ransom note.

06

The four pieces

The genealogy tree is not one drawing. It is four independent pieces, and that is the whole reason a single set of assets can serve both layouts.

Drag the handle at the bottom-right corner of the frame below to narrow it. Nothing swaps files, nothing is redrawn — only the branch changes length, and below 620px it goes away entirely and the camera sits directly on the trunk.

/* three tracks, not twelve. the spine is fixed
   because the trunk's stroke weight must NOT
   scale with the viewport. */
.era {
  display: grid;
  grid-template-columns: 1fr var(--spine-w) 1fr;
}
:root { --spine-w: clamp(56px, 7vw, 96px); }

@media (max-width: 620px) {
  .era { grid-template-columns: 1fr; }
  .era__branch { display: none; }
}

The trunk stays centred in both layouts, which is what lets the canopy — symmetric, and centred by construction — sit on top of either without a second version of the drawing.

Note what is not here: no fixed artboard, no transform: scale(), no measured heights. The current genealogy page scales a 1200px board down to fit, which on a 390px phone is 0.285 — 16px body text arriving as 4.6px. Flow layout removes the whole class of problem rather than tuning it.
